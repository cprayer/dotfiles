# 완료 기준 — 실행 증거

빌드·테스트 통과만으로 작업 완료로 간주하지 않는다. 실제로 실행해 확인한 것만 완료다.

## 로컬 구동 + API 응답 검증

API 응답에 영향을 주는 변경은 아래까지 끝나야 완료다.

- 변경한 서비스를 로컬에서 구동 (예: `./gradlew :module-name:bootRun`)
- 관련 API/엔드포인트를 직접 호출 (curl, grpcurl, Postman 등)해 **응답이 의도한 대로 수정되어 내려오는지** 확인
- 응답 필드/값/구조가 의도와 다르면 코드 수정 → 다시 검증
- 로컬 구동이 불가능한 변경(설정 파일, 문서, 스킬 정의 등)은 생략 가능. 단, 생략 사유를 명시할 것

## 보고 방식

- "검증했다 / 통과한다"고 보고하기 전에 실제 명령을 실행하고, 실행한 명령과 결과(성공·실패 개수)를 증거로 함께 적는다. 추정 기반 완료 보고는 하지 않는다
- 동작·버그 여부를 정적 추론으로 단정하지 않는다. 기존 로직을 변형하지 말고 그대로 실행해 재현한 뒤 '실측'과 '추론'을 구분해 보고한다
- 검증 단계 중 하나라도 실패하면 문제를 해결한 뒤 완료로 본다
