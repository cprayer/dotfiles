# 코드 주석 · 로깅 메시지

## 주석

- **주석 0개가 기본값이다.** 새 코드에 주석을 넣기 전에 "코드만 봐서는 절대 알 수 없는 WHY 인가"를 자문하고, 아니면 넣지 않는다
  - 금지: 설계 결정 배경·히스토리·필드 유래 설명 주석 (그 내용은 PR 본문이나 커밋 메시지로)
  - 금지: `// ===== List =====` 같은 구분선 주석, WHAT 을 다시 말하는 주석
  - 식별자(함수명/파라미터명/타입)로 의도가 전달되면 생략. 남기더라도 1-2줄
  - 예외: 사용자가 명시적으로 주석 추가를 요청한 경우
- 문장 끝에 마침표(`.`)를 붙이지 않는다
  - 예: `// outer span 추가` (O) / `// outer span 추가.` (X)
  - 여러 문장으로 구성된 주석에서도 **마지막 문장의 끝 온점**만 생략
- 여러 줄 주석은 `//` 를 반복하지 않고 `/* */` 블록으로 작성한다 (각 줄에 ` * ` prefix 권장). KDoc/JavaDoc 이 필요한 곳은 `/** */` 그대로 사용
- **실측 삭제 요청 서명** (2026-08-12~08-24, 6회 — 규칙 작성 이후 재발분이다). 아래 형태는 WHY 라도 남기지 않는다. 나중에 지우는 게 아니라 **처음부터 쓰지 않는다**
  - `—` / `왜냐하면` / `~라서` 로 설계 근거·트레이드오프를 덧붙이는 주석
  - 2줄 이상 블록으로 **동작 배경을 설명**하는 주석 (바로 위 형식 규칙은 "여러 줄을 꼭 써야 할 때의 형식"이지, 배경 설명을 허용한다는 뜻이 아니다)
  - 지금 구현에만 맞는 설명 — 구현이 바뀌면 거짓이 되는 주석
  - 코드 밖 액션의 소관을 적는 주석도 대상이다
- 사용자가 "주석 빼줘" 를 한 번이라도 말한 세션에서는, 그 세션 남은 동안 **새 주석을 0개로 유지한다**
- 기존 코드를 수정할 때 원래 있던 주석은 요청 없이 손대지 않는다 (추가만 억제한다)

## 로깅 메시지

- 모든 logger 메시지(`logger.info/warn/error/debug`, `log.info(...)` 등 어떤 로깅 라이브러리든)는 **영어**로 작성한다
  - 예: `logger.warn { "Langfuse prompt warmup failed: name=$name" }` (O)
  - 예: `logger.warn { "Langfuse prompt warmup 실패: ..." }` (X)
  - 예외: 로그 본문에 포함된 데이터 값(쿼리 문자열 등)은 그대로 유지
- silent 경로 관측용 warn 같은 방어적 로그는 사용자가 요청한 경우에만 추가한다
