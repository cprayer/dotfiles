# 이전 세션 찾기 → 재개 → 컨텍스트 회수

이 사용자는 하나의 작업이 여러 세션에 걸치는 것이 기본 워크플로우다. "이전에 ~했었는데" 는
기억이 아니라 **`~/.claude/projects/**/*.jsonl` 에 남아있는 조회 가능한 사실**이다.
현재 대화 transcript 를 보는 것은 이 소스가 아니며, 없다고 답하기 전에 반드시 아래 ①을 실행한다.

## ① 주제어 추출

프롬프트 원문이 아니라 **주제의 의미**로 검색어를 만든다. 2~4개를 뽑아 OR 로 넣는다.

- 고유명사·식별자 우선: 티켓 키, DAG 이름, 서비스명, PR 번호
- 한글 도메인어와 영문 심볼을 **둘 다** 넣는다 (`히어로 배너` + `hero`)
- 사용자가 "부하도 측정했던" 처럼 행위로 말하면 행위어도 넣는다 (`부하`, `측정`)

## ② 전 디렉토리 검색

프로젝트 디렉토리가 대화 주제와 일치하지 않는 경우가 잦으므로 **`~/.claude/projects/` 전체**를 훑는다
(스크립트가 이미 전체를 대상으로 한다. 특정 디렉토리로 좁히지 말 것).

```bash
python3 ~/.claude/skills/session-resume/find_session.py "주제어1" "주제어2" \
  --limit 5 --exclude <현재_세션_id>
```

- `--exclude` 에는 현재 세션 id 를 넣는다. scratchpad 경로의 UUID 성분이 그 값이다
  (`/private/tmp/.../<프로젝트>/<세션UUID>/scratchpad`). 안 넣으면 지금 이 세션이 1위로 잡힌다
- 전체 1.6GB / 3300여 파일에서 약 1초. `--days 30`, `--cap` 으로 범위 조절
- 0건이면 주제어를 바꿔 최소 2회 더 시도한다. 1회 실패로 "기록이 없다"고 답하지 않는다

랭킹은 `(일치한 주제어 개수, 점수, 최신순)`. 사람이 친 프롬프트와 세션 제목만 대상이라
tool 출력 노이즈에 끌려가지 않는다.

## ③ 후보를 제시하고 사용자 확인을 받는다

1위를 단정하지 말고 **상위 3~5개를 제목·기간·cwd·첫/끝 프롬프트와 함께 제시**하고 고르게 한다.
랭킹은 틀릴 수 있고, 잘못 고르면 한 턴을 더 쓴다 (실제로 그렇게 소모된 사례가 있다).

## ④ 확정된 세션에서 컨텍스트를 전량 회수 — 가장 중요한 단계

```bash
python3 ~/.claude/skills/session-resume/find_session.py --dump <세션_id>
```

출력에서 아래를 뽑아 **작업 시작 전에 사용자에게 요약 보고**한다.

- **출처 링크** — 슬랙 스레드 / 지라 티켓·티켓키 / 노션 / 구글독 / PR. 사용자가 나중에 다시
  붙여넣게 만들지 않는다. 이전 세션 안에 이미 있는 링크를 안 꺼내서 생기는 마찰이다
- **작업 상태** — `cwd`, 등장한 `gitBranch`, PR 번호, 지라 티켓 ID
- **미완 항목** — 사람 프롬프트 전량을 훑어 마지막 지시·보류 사항·사용자가 명시한 설계 결정을 뽑는다.
  이미 접힌 대안을 재제안하지 않기 위해 필요하다
- Datadog 등 초장문 URL 은 표시 시 잘린다. 원문이 필요하면 출력 상단의 `file:` 경로를 직접 grep 한다

`claude --resume <id>` 는 **사용자가 직접 실행하는 경우에만** 안내한다. 스킬이 대신 실행하지 않는다.
현재 세션에서 이어서 하는 것이 기본이며, 회수한 컨텍스트를 이 세션으로 가져와 진행한다.

## ⑤ 착수

④에서 브랜치를 찾았으면 새로 만들지 말고 그 브랜치에서 이어간다.

## 이 스킬을 쓰지 않는 경우

MySQL 세션 / JWT·HTTP Session / Datadog `session_id=` 파라미터 / UBA 세션 분석 /
현재 세션의 서브에이전트 — 전부 대상이 아니다. "세션" 이라는 단어만으로 실행하지 말고,
**과거 대화 기록을 찾는 것이 목적일 때만** 실행한다.
